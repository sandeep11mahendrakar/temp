## D. Context-efficiency measurement

Measurement used PowerShell `Get-Item` byte counts, whitespace word counts, and the exact formatted excerpt strings produced by `Search-ProjectContext.ps1`. The “broad packet” is an explicit 15-file comparison set: task board, intercom, suggestions, worker/verifier/audit-lite prompts, Claude checkpoint dump, TodoMVC run analysis, project handoff, OpenCode JSONL, architecture, limitations, final state/evaluation, and claims matrix.

| Mode | Files/text measured | Bytes | Words/chars |
|---|---|---:|---:|
| Broad full-read comparison | 15 selected files, full contents | 802,919 bytes | 104,248 whitespace-delimited words |
| Compact entry files | Repo `AGENTS.md` plus `CODEX_PROJECT_MEMORY.md` | 4,328 bytes | 544 words; `AGENTS.md` itself is 179 words |
| Task-specific retrieval simulation | 11 bounded search/status results for the 7 question set | — | 6,569 formatted chars / 742 words |

The search-output packet is about **99.3% fewer words** than loading that defined broad file set. A rough `chars ÷ 4` heuristic estimates about **1,647 tokens** for that excerpt packet only; it is not a tokenizer result. This is a repeatable text-volume comparison, not an observed Codex input-token bill: global/developer instructions, skill metadata, automatic context, internal tool routing, and any extra follow-up reads are excluded. The 4,328-byte compact pair is not automatically all loaded: repository `AGENTS.md` is the persistent instruction; the memory and full skill bodies are retrieved on demand, while skill names/descriptions were visible in this session's catalog.

No claim of exact token savings is made. The migration improves bounded retrieval for tested questions, but broad audits still require additional files and therefore more context.
